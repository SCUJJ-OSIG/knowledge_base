## 1. 单一职责原则

一个组件只做一件事：

- 弹窗只负责弹出 / 关闭，表单只负责收集校验，表格只负责渲染分页筛选；
    
- 复杂页面拆成「容器组件（逻辑）+ 展示组件（纯 UI）」分层；
    
- 禁止一个组件同时处理接口、弹窗、表单、权限、打印。
    

## 2. 开闭原则：对扩展开放，对修改关闭

不要改组件内部代码适配新需求，而是通过 `props / slots / emits / expose` 扩展能力：

- 新增功能优先加属性，不修改原有逻辑；
    
- 样式、内容、渲染结构全部交给插槽自定义。
    

## 3. 单向数据流（Vue 灵魂）

- **父传子只用 props**，禁止子组件直接修改 props；
    
- 子组件修改数据必须 `emit` 事件通知父，父改原数据；
    
- 复杂对象 props 内部先解构副本，只读不写源对象。
    

## 4. 解耦 & 高复用：抽离可变与不变

不变逻辑留在组件内部（基础交互、默认样式、基础请求）； 可变内容全部对外暴露：

- 可变文本：props
    
- 可变 DOM 结构：插槽 slot
    
- 可变行为：自定义事件 emit
    
- 可变实例方法：defineExpose
    
- 可变样式：class、style、自定义 css 变量
    

## 5. 配置驱动（高级复用核心）

不用写大量 v-if/v-for，用数组配置渲染：表格列、表单项、菜单、标签页统一用 `options` 数组驱动，一套配置到处用。

## 二、Props 封装最佳技巧（最常用，避坑重点）

### 1. 严格校验 props，默认值完整定义

Vue3 + TypeScript 推荐 `withDefaults + defineProps`

```ts
const props = withDefaults(defineProps<{
  title?: string
  pageSize?: number
  disabled?: boolean
  rowList?: any[]
}>(), {
  title: '',
  pageSize: 10,
  disabled: false,
  rowList: () => [] // 对象/数组默认值必须函数返回
})
```

**规范**：

- 必传参数不加 `?`，非必传给默认值；
    
- 数组、对象默认值不能直接写 `[]`，必须工厂函数；
    
- 复杂类型用 `PropType` 标注类型，加 validator 自定义校验。
    

### 2. 拆分基础属性与业务属性

基础 UI 属性：`size、disabled、loading、placeholder、readonly`（通用所有输入类组件） 业务属性：`api、queryParams、treeKey` 业务专属参数，分开维护可读性更强。

### 3. 透传属性 `$attrs` 技巧（无需重复定义 props）

封装二次封装 el-input /el-table 时，不用把原生属性挨个定义 props，直接透传：

```vue
<!-- 模板 -->
<el-input v-bind="$attrs" v-model="innerValue" />

<!-- script -->
defineOptions({ inheritAttrs: false }) // 关闭自动根节点继承，避免样式污染
const attrs = useAttrs() // 手动控制透传
```

适用场景：二次封装第三方 UI 组件、基础输入框、按钮。

### 4. 禁止直接修改 props

错误：`props.innerValue = 'xxx'` 正确：内部创建计算属性中转

```ts
const innerValue = computed({
  get() { return props.modelValue },
  set(val) { emit('update:modelValue', val) }
})
```

### 5. 支持 v-model 多双向绑定

Vue3 支持多 v-model，封装复杂表单组件必备：

```ts
const emit = defineEmits(['update:modelValue', 'update:visible'])
// 使用：<MyDialog v-model:visible="show" v-model="formData="data" />
```

## 三、Slot 插槽分层封装（实现高度自定义）

### 1. 插槽分类规范

1. **默认插槽**：整体替换组件主体
    
2. **具名插槽**：局部替换（header /footer/prefix /suffix）
    
3. **作用域插槽**：子组件数据传给父自定义渲染（表格单元格、下拉选项）
    

示例：通用弹窗封装

```vue
<!-- 组件内部 -->
<div class="dialog-header">
  <slot name="header"> {{ props.title }} </slot>
</div>
<div class="dialog-body">
  <slot />
</div>
<div class="dialog-footer">
  <slot name="footer">
    <el-button @click="close">取消</el-button>
    <el-button type="primary" @click="confirm">确定</el-button>
  </slot>
</div>
```

### 2. 作用域插槽高阶技巧（表格封装标杆）

```vue
<!-- 子组件 Table -->
<el-table-column v-for="col in props.columns" :key="col.prop" :label="col.label">
  <template #default="scope">
    <!-- 优先使用父传入的自定义插槽 -->
    <slot :name="col.prop" v-bind="scope" />
    <!-- 无插槽则使用默认渲染 -->
    <span v-if="!$slots[col.prop]">{{ scope.row[col.prop] }}</span>
  </template>
</el-table-column>
```

父组件使用：只需要自定义某一列，其余自动渲染

```vue
<MyTable :columns="columns">
  <template #status="scope">
    <el-tag :type="scope.row.status === 1 ? 'success' : 'danger'">
      {{ scope.row.statusName }}
    </el-tag>
  </template>
</MyTable>
```

### 3. 判断插槽是否传入（控制默认内容显隐）

```ts
const slots = useSlots()
// 判断是否存在footer插槽
const hasFooter = computed(() => !!slots.footer)
```

## 四、事件 emit 封装规范

1. 命名统一：小驼峰，更新数据统一 `update:xxx` 配合 v-model；
    
2. 事件传参标准化：统一传递 `(value, row, index)` 三元参数；
    
3. 内置原生事件透传：结合 `$attrs` 把 click/change 透传给内部原生组件；
    
4. 不冗余触发：内部防抖节流，避免高频 emit。
    

示例标准定义：

```ts
const emit = defineEmits([
  'update:modelValue',
  'search',
  'row-click',
  'confirm',
  'close'
])
```

## 五、defineExpose 暴露实例方法（父调用子组件能力）

适合弹窗、表格、上传、表单等需要父主动调用内部方法的组件：

```ts
const openDialog = () => { show.value = true }
const resetForm = () => { /* 重置表单 */ }

defineExpose({
  openDialog,
  resetForm
})
```

父组件通过 `ref` 直接调用：

```vue
<MyDialog ref="dialogRef" />
const dialogRef = ref()
dialogRef.value.openDialog()
```

## 六、样式封装技巧（隔离、可定制）

### 1. scoped + 深度选择器，不污染全局

```vue
<style scoped>
/* 修改内部第三方组件样式 */
:deep(.el-input__inner) {
  border-radius: 8px;
}
</style>
```

### 2. CSS 变量实现外部自定义主题（最优解）

组件内部：

```vue
<style scoped>
.box {
  --bg-color: #fff;
  background: var(--bg-color);
}
</style>
```

父组件传样式变量：

```vue
<MyComponent style="--bg-color:#f5f7fa" />
```

### 3. 多类名合并工具函数

封装统一合并 class，支持数组、对象、字符串，兼容外部 `class` 透传。

### 4. 根节点合并外部 class

```vue
<div :class="[$attrs.class, 'my-component-wrap']">
```

## 七、配置驱动封装实战思想（表格 / 表单最强复用方案）

### 通用表单封装示例思路

1. props 接收 `formModel` 绑定表单数据，`formOptions` 配置表单项；
    
2. `formOptions` 数组配置每一项：label、prop、type、rules、placeholder、slotName；
    
3. 内部 v-for 循环渲染输入组件；
    
4. type 区分 input/select/date/radio，自动渲染对应控件；
    
5. 支持作用域插槽自定义任意表单项；
    
6. expose 暴露 `validate()` / `resetFields()` 校验重置方法。
    

```ts
// 配置样例
const formOptions = [
  { label: '姓名', prop: 'name', type: 'input', rules: [{ required: true, message: '必填' }] },
  { label: '状态', prop: 'status', type: 'select', options: [{ label: '启用', value: 1 }] }
]
```

优势：新增表单页面不用重复写一堆 el-form-item，只传配置数组，大幅减少模板代码。

## 八、抽离逻辑：组合式函数 useXXX（封装逻辑，组件轻量化）

把请求、分页、搜索、树操作、表单校验等通用逻辑抽成 hooks，组件只做 UI 渲染：

```ts
// useTable.ts 表格通用逻辑
export function useTable(api) {
  const tableData = ref([])
  const page = ref({ pageNum:1, pageSize:10 })
  const loading = ref(false)
  const getList = async () => {
    loading.value = true
    tableData.value = await api(page.value)
    loading.value = false
  }
  return { tableData, page, loading, getList }
}
```

组件内直接引入，逻辑完全复用，组件代码极简。

## 九、通用高级封装技巧

### 1. 全局注册 & 按需导入双兼容

组件内 `install` 方法，支持 `app.use()` 全局注册，也支持单独 import 按需引入。

### 2. 自动防抖、节流内置

输入框、搜索框组件内部封装防抖，通过 props `debounce` 控制延迟时间，父无需重复写防抖。

### 3. 权限内置封装

增加 `auth` props，组件内部判断权限，无权限自动隐藏按钮 / 输入框，业务页面不用到处写 v-if 权限判断。

### 4. 懒加载、虚拟滚动内置

大数据表格、下拉组件内部封装虚拟列表，通过 `virtual` props 开关，外部零改造。

### 5. 兼容空状态、加载、无数据

所有列表类组件内置 loading、empty 空插槽，统一空数据展示，不用每个页面重复写空状态。

### 6. 递归组件封装（树形组件、多级菜单）

自身调用自身 slot + props 递归渲染，只靠一份配置渲染无限层级树。

### 7. 异步组件封装（弹窗懒加载）

大型弹窗、复杂表单使用 `defineAsyncComponent` 懒加载，减少首屏打包体积。

## 十、避坑清单（新手最容易踩的封装错误）

1. props 对象深度监听，直接用 watch 浅层监听导致数据不更新 → 使用 `watch(props.rowList, { deep: true })`
    
2. 组件根节点多个，透传 class/style 失效 → 保证单根节点
    
3. 大量重复 props 定义，忘记透传 $attrs → 二次封装 UI 组件统一透传属性
    
4. 子组件直接修改父 props，数据流混乱 → 全部通过 emit 更新
    
5. 插槽不做判空，默认内容无法隐藏 → useSlots 判断插槽存在性
    
6. 样式不加 scoped，全局样式冲突 → 所有组件 style 加 scoped
    
7. 业务逻辑全写在组件内，无法复用 → 公共逻辑抽离 hooks
    
8. 组件职责过重，几百行代码不拆分 → 拆容器 / 展示组件，抽公共逻辑

## 十一、分层封装落地架构（企业级标准）

1. **基础底层组件**：二次封装 Element Plus / Vant 原生组件（Input、Button、Table、Dialog），统一尺寸、样式、透传属性；
    
2. **通用业务组件**：基于底层封装带业务逻辑（搜索表格、弹窗表单、文件上传、树形选择器），配置驱动；
    
3. **页面业务组件**：页面独有模块，不可复用，只使用前两层通用组件；
    
4. **hooks 工具层**：纯逻辑抽离，无 DOM，全项目复用。
