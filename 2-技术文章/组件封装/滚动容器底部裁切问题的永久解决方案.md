## 一、先把 3 个核心尺寸、margin、padding 底层原理拆干净，不打比方，纯 CSS 规则

### 1. 三个关键高度定义（`overflow:auto` 容器专属）

1. `clientHeight` 滚动容器**可视窗口高度**，就是你眼睛能看到的区域，固定不变。
    
2. `scrollHeight` 容器内部**所有内容的完整高度**，用来计算最多能滚多少。 计算规则：包含内部所有元素内容高度 + **子元素垂直外边距 margin-top/margin-bottom**。
    
3. 最大可滚动值公式（浏览器硬性规则） `maxScrollTop = scrollHeight - clientHeight` 当 `scrollTop = maxScrollTop`，代表内容已经滚到理论最底部。
    

### 2. padding 和 margin 本质区别（关键分水岭）

1. `padding`：元素**内部留白**，属于盒子自身区域，永远被包裹在容器可视区内，不会溢出。
    
2. `margin`：元素**外部留白**，是元素和其他元素之间的空隙，不属于容器内部可视区域。
    

### 3. 遮挡发生的完整原理链条（一步一步）

1. 你的滚动容器 `.scroll-view`：只有 `overflow:auto`，**没有 padding-bottom**
    
2. 插槽内部有 `<p>`、标题等标签，浏览器默认自带 `margin-bottom`
    
3. 计算 `scrollHeight` 时，会把最后一段文字的 `margin-bottom` 算进总高度里
    
4. 浏览器算出最大滚动距离 = 文字总高 + 末尾 margin 高度 - 容器可视高度
    
5. 你滚轮滑到最底部，`scrollTop` 达到最大值，内容整体向上偏移到极限
    
6. 此时画面状态： 最后一段文字的底边，对齐滚动容器的可视底边； 而那一段参与计算的 `margin-bottom`，在文字**下方**，直接跑到容器可视区域外面。
    
7. 肉眼效果：文字贴住容器下边框，下半部分被裁切，少一截看不见。
    

#### 核心矛盾一句话

margin 参与滚动高度计算，但渲染位置在容器可视区外，滚动极限时直接溢出消失，连带文字被挡住。 padding 不会出现这个问题，因为它永远在盒子内部。

## 二、一劳永逸永久根治方案：内层包装器（推荐全局通用，写一次终身不用管）

### 思路底层逻辑

新增一层内部容器，把所有插槽内容全部包起来，做两件事：

1. 清除内部所有子元素的 `margin-bottom`，从源头消除参与高度计算的多余外边距；
    
2. 给内层容器设置底部 `padding-bottom`，用**内部留白**替代外部 margin，留白永远在可视区里，不会溢出。
    

双重保险，不管外面传什么杂乱的 p、h 标签、markdown 文本，永远不会底部裁切。

### 修改后完整代码

```vue
<script setup lang="ts">
import { ref } from 'vue'

const props = defineProps<{
  maxHeight?: string
  maxWidth?: string
}>()

const elRef = ref<HTMLDivElement>()

function onWheel(e: WheelEvent) {
  if (!elRef.value) return
  const el = elRef.value
  if (e.shiftKey) {
    e.preventDefault()
    el.scrollLeft += e.deltaY
  }
}
</script>

<template>
  <!-- 外层滚动容器，只负责滚动、隐藏滚动条 -->
  <div
    ref="elRef"
    class="scroll-view"
    :style="{
      maxHeight: maxHeight || '100%',
      maxWidth: maxWidth || '100%',
    }"
    @wheel="onWheel"
  >
    <!-- 内层包装器：一劳永逸处理margin、底部缓冲 -->
    <div class="scroll-inner">
      <slot />
    </div>
  </div>
</template>

<style scoped>
.scroll-view {
  @apply overflow-auto;
  scrollbar-width: none;
  -ms-overflow-style: none;
}
.scroll-view::-webkit-scrollbar {
  display: none;
}

/* 内层包装器永久修复配置 */
.scroll-inner {
  /* 底部内边距缓冲，留白永远在容器内部，不会溢出 */
  padding-bottom: 1.5rem;
}

/* 清空所有子元素底部外边距，从根源消除多余scrollHeight增量 */
.scroll-inner :deep(p),
.scroll-inner :deep(h1),
.scroll-inner :deep(h2),
.scroll-inner :deep(h3),
.scroll-inner :deep(div) {
  margin-bottom: 0;
}
</style>
```

## 三、为什么这个方案能永久解决，不会复发？

### 第一层保障：清除所有子元素 margin-bottom

所有插槽内容的段落、标题底部外边距直接归零。 `scrollHeight` 不再包含多余的末尾 margin 高度，浏览器计算的最大滚动距离，刚好等于纯文字高度差。 滚动到极限时，文字底边刚好落在缓冲 padding 上方，不会贴边框裁切。

### 第二层保障：内层统一 padding-bottom

哪怕后续业务新增标签、忘记清 margin，底部自带一段内部留白缓冲。 padding 属于盒子内部空间，无论怎么滚动都不会跑到可视区域外，始终给底部文字留出安全距离，杜绝裁切。

### 对比另外两种临时方案的短板

1. 只给外层加 `padding-bottom`： 外层 padding 会让**上下整体内缩**，顶部也多出空白，破坏页面排版，只能临时救急，不通用。
    
2. 只清除 margin 不套内层： 外部直接穿透 slot 写深度选择器，外部样式容易覆盖、污染组件，多个滚动组件会互相冲突，无法复用。
    

## 四、总结最简原理记忆

1. 遮挡根源：末尾 `margin-bottom` 计入滚动高度，但渲染在容器可视区外部，滚到底直接溢出；
    
2. 永久根治逻辑：内层包装器「清零底部 margin + 内置底部 padding 缓冲」；
    
3. 优势：封装在组件内部，外部使用组件时无需额外处理任何文本样式，全局通用、永不复发底部裁切。
