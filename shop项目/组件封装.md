要打造一个复用率最高、且深度集成骨架屏（Skeleton）的“万能”图片组件，其核心秘诀在于：**彻底分离“布局逻辑”与“加载逻辑”**。

一个顶级的通用图片组件应该像一个**“智能容器”**，它能感知环境、处理异常，并对开发者保持极简的接口。以下是实现高复用率的 5 个关键维度：

---

### 1. 自动化的加载状态全生命周期管理

复用率高的组件不应该让开发者在外面手动写 `isLoading`。骨架屏必须封装在组件**内部**，并自动根据以下状态切换：

- **API 层面**：如果传入的是 `imageId`，内部自动处理数据请求，显示骨架。
    
- **资源层面**：URL 拿到了，但在浏览器下载完成前，继续显示骨架。
    
- **平滑过渡**：图片加载完后，通过 `opacity` 渐变展示，避免图片“刷”地一下跳出来。
    

---

### 2. 响应式布局的“变色龙”能力

正如你之前的需求，最高级的复用是：**同一个组件，在不同屏幕下改变其渲染模式**。

- **支持“内容撑起”模式**：用于文章、广告，图片原样显示，不被裁剪。
    
- **支持“容器填充”模式**：用于头像、卡片、背景，图片填满固定格子。
    
- **通过 `fill` 属性透传**：利用 Next.js 的 `fill` 配合 CSS 的 `aspect-ratio`，让组件能自动适配父级的尺寸。
    

---

### 3. 防御性设计：容错与占位

复用率高的组件必须“坚不可摧”。无论后端给的是空字符串、坏链接还是错误的 ID，它都不能崩：

- **Error Boundary**：图片加载失败时，自动切换到 `AlertCircle` 这种错误图标。
    
- **Fallback**：如果没有图片，显示一个优雅的占位图（Placeholder）。
    
- **骨架屏常驻**：在配置下，即使报错也可以选择保留骨架屏，防止 UI 闪烁。
    

---

### 4. 极致的性能黑盒

开发者只需传一个 `src`，剩下的性能优化全由组件内部完成：

- **自动 WebP/AVIF 转换**：利用 Next.js 引擎。
    
- **懒加载（Lazy Loading）**：默认开启，除非传入 `priority`。
    
- **预取逻辑**：自动处理关键图片的 `LCP` 优化。
    

---

### 5. 属性透传（Boss 级封装）

为了保证“复用”而不失去“灵活性”，必须支持 **Props 透传**。

这样当开发者突然需要给某一张图片加 `quality={100}` 或者 `onDoubleClick` 时，不需要修改组件内部，直接在外面写就行。

---

### 总结：理想的调用方式应该是怎样的？

TypeScript

```
// 场景 A：轮播广告（桌面填充，手机自适应）
<ImageComponent 
  imageId={ad.id} 
  fill={isDesktop} 
  aspectRatio="aspect-video md:aspect-none" 
/>

// 场景 B：用户头像（固定圆形，强制高画质）
<ImageComponent 
  src={user.avatar} 
  className="rounded-full w-12 h-12" 
  quality={100} 
/>

// 场景 C：文章详情（原始尺寸，带骨架屏）
<ImageComponent 
  src={article.cover} 
  fill={false} 
/>
```

### 为什么这样复用率最高？

因为你把 **“脏活累活”**（判断 window 宽度、处理加载状态、写骨架屏 CSS、处理图片报错）全部锁死在了组件内部。对于其他开发者来说，它就是一个**“丢进去就能用，且绝对不会报错”**的黑盒。
