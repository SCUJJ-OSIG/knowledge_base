## Overview

This proposal introduces a breaking API redesign for Cerebro aiming to fix long-standing DX pain points:

1. Replace `options: OptionConfig[]` → `options: Record<string, OptionConfig>` to eliminate mandatory `as const`
    
2. Unify argument API: remove single `argument`, only keep `arguments` object (align with bune)
    
3. Add `defineCommand` factory for automatic type inference of `ctx.args` / `ctx.options` inside `execute()`
    
4. Adopt Elysia-like chained generic accumulation on `addCommand`, return new Cerebro instance instead of mutating `this`
    
5. Minimal runtime changes: normalize object options into array internally to reuse existing parser logic
    

> Scope: Type layer heavy lifting, runtime parsing only needs small normalization adapter.

## Key Pain Points Today

- Users must add `as const` everywhere on options array for type inference
    
- Dual API: `argument` / `arguments` creates confusion
    
- Context inside `execute()` cannot infer args/options automatically; users need manually define interfaces
    
- Cannot collect command names statically for type-safe command dispatch
    
- Array-based options make extracting option names harder on type level
    

## Proposed API Changes (Breaking Changes)

### 1. Deprecated old shape

```ts
// ❌ Removed
{
  argument: { name: "...", type: ... },
  options: [ { name: "...", alias: "l", type: Boolean } ]
}
```

### 2. New standard command shape

```ts
{
  name: "greet",
  description?: string,
  arguments: {
    username: { type: String, required: true, description: "Target username" }
  },
  options: {
    loud: { alias: "l", type: Boolean, description: "Output uppercase" }
  },
  execute: (ctx) => {}
}
```

### 3. New `defineCommand` factory

Captures command configuration literal types, automatically infer `CommandContext` for execute callback:

```ts
const greet = defineCommand({
  name: "greet",
  arguments: { username: { type: String, required: true } },
  options: { loud: { alias: "l", type: Boolean } },
  execute(ctx) {
    // ctx.args.username: string
    // ctx.options.loud: boolean | undefined
  }
});
```

### 4. Chained generics on `addCommand`

`addCommand` returns brand new `Cerebro<Commands>` instance instead of `this`, accumulates command type map:

```ts
const cli = new Cerebro()
  .addCommand(greet)
  .addCommand(buildCommand);
// Cerebro<{ greet: InferShape; build: InferShape }>
```

Enables future feature like `runTyped()` with type-checked command name.

## Runtime Compatibility Strategy

No full rewrite of argv parser: Add internal normalization function to convert `Record<string, OptionConfig>` → `OptionConfig[]` before passing into existing parser.

```ts
function normalizeCommand(cmd: CommandShape) {
  const optionsArray = Object.entries(cmd.options ?? {}).map(([name, opt]) => ({
    name,
    ...opt
  }));
  return { ...cmd, options: optionsArray };
}
```

## Core Design Principles

1. **`defineCommand`** **and chained generics are complementary, not mutually exclusive**
    
    1. Chained generics on Cerebro: collect top-level command names for outer CLI instance
        
    2. `defineCommand`: derive precise `ctx` types inside execute handler
        
    3. Only using chained generics cannot infer context inside execute callback
        
2. Maximize reuse of existing parsing runtime logic, isolate breaking changes to public API & type definitions
    
3. Align API design with popular CLI tooling (bune) to lower learning curve
    

## Migration Guide for Users

```ts
// Old
cli.addCommand({
  name: "greet",
  argument: { name: "username", type: String, required: true },
  options: [{ name: "loud", alias: "l", type: Boolean }],
  execute(ctx) => {}
})

// New
const greet = defineCommand({
  name: "greet",
  arguments: { username: { type: String, required: true } },
  options: { loud: { alias: "l", type: Boolean } },
  execute(ctx) => {}
})
cli.addCommand(greet);
```
