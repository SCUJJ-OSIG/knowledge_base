# Everything 搜索语法完整通俗解读

这份文档是 **Everything（Windows 文件搜索神器）** 的搜索表达式语法手册，我分层拆解，先理清基础结构、运算符、通配符、修饰符、宏、转义实体，最后附带实例方便你直接上手。

> 前置概念： 一个文件路径 `C:\folder\file.txt`
> 
> - **完整路径**：`C:\folder\file.txt`
>     
> - **名称 (name)**：`file.txt`
>     
> - **路径 (path)**：`C:\folder`
>     
> - **茎干 (stem)**：`file`（文件名去掉后缀）
>     
> - **扩展 (extension)**：`txt`
>     

## 一、最小单元：单个搜索词基础格式

```Plain
[!][search-modifier:][search-function:]<text>
```

逐层拆分：

1. `[!]` 可选：**取反（NOT）**，代表排除这个条件
    
2. `[search-modifier:]` 可选：**搜索修饰符**，临时修改匹配规则（大小写、重音敏感等） 例：`case:` 区分大小写、`diacritics:` 区分重音符号
    
3. `[search-function:]` 可选：**搜索功能 / 字段筛选**，限定只匹配文件某一部分
    
    |   |   |
    |---|---|
    |字段|作用|
    |`path:xxx`|在**完整路径**搜索 xxx|
    |`name:xxx`|只匹配文件名（不含上层目录）|
    |`stem:xxx`|匹配文件名主干，忽略后缀|
    |`extension:xxx`|匹配文件后缀|
    |`date-modified:today`|修改日期筛选|
    
4. `<text>`：真正要搜索的文本 / 值
    

### 简单例子对照

- `abc`：默认，匹配**文件名**包含 `abc`
    
- `path:abc`：匹配**完整路径**任意位置包含 `abc`
    
- `extension:JPG`：后缀是 JPG（默认不区分大小写，搭配修饰符可强制区分）
    
- `!abc`：排除所有名字包含 abc 的文件
    
- `case:extension:JPG`：区分大小写，只匹配大写`.JPG`，jpg 不匹配
    

## 二、逻辑运算符（多个搜索词组合）

> 默认优先级：**OR 高于 AND**（先算或，再算和），可以用 `<>` 括号改变运算顺序

### 1. 空格 = AND（同时满足）

```Plain
abc 123
```

等价：`abc AND 123` 👉 文件名称**同时包含 abc 和 123**

### 2. `|` = OR（满足任意一个）

前后空格无所谓，`abc|123` / `abc | 123` 效果一样

```Plain
abc | 123
```

👉 文件包含 abc **或者** 包含 123

### 3. `!` = NOT（排除，紧跟搜索词）

```Plain
!abc
```

👉 文件**不能包含**abc

### 4. `< >` 分组括号，改变运算优先级

举个官方例子：

```Plain
!<abc 123>
```

拆解：先要求**同时包含 abc 和 123**，然后整体取反 👉 **不匹配同时带有 abc+123** 的文件；只有 abc、只有 123 的文件依然会被搜到

#### 优先级对比示例

原生规则：`apple banana | orange` 自动解析：`(apple banana) | orange` 含义：（同时有 apple+banana）**或者** 有 orange

想要效果：apple +（banana 或 orange），必须手动分组

```Plain
<apple banana | orange>
```

### 5. `" "` 双引号：原始文本，关闭运算符功能

引号内部所有符号**不再是命令，单纯当成普通文字**

```Plain
"C:\Program Files"
```

直接搜索字面字符串 `C:\Program Files`，空格不会被当成 AND 运算符。

## 三、通配符 Wildcard

> ⚠️ 使用通配符时，**完整名称整体匹配**，不是模糊包含！ | 符号 | 规则 | | ---- | ---- | | `*` | 匹配 0 个或多个字符，**不能匹配反斜杠** **`\`****（不能跨目录）** | | `**` | 匹配 0 个或多个字符，**可以包含 \，跨目录匹配** | | `?` | 匹配**单个任意字符**，不能匹配 `\` |

实例：

- `*.mp3` → 所有后缀 mp3 文件
    
- `foo*` → 名称**以 foo 开头**
    
- `*foo*` → 名称**包含 foo**
    
- `stem:*bar` → 文件主干（去掉后缀）以 bar 结尾
    

## 四、内置媒体宏（简写过滤器）

不用手动写后缀集合，一键筛选文件类型

```Plain
audio:     # 音频文件
archive:   # 压缩包（zip/7z/rar等）
doc:       # 文档
exe:       # 可执行程序
image:     # 图片
video:     # 视频
```

示例：

```Plain
audio:                # 全部音频
audio: | video:       # 音频 或者 视频
```

## 五、字符实体（转义！重点）

如果你搜索的文本**本身包含运算符符号**（空格、|、!、"、< >），直接写会被当成指令，必须使用实体转义！

|   |   |   |   |
|---|---|---|---|
|实体代码|代表字面字符|使用场景||
|`&sp:`|空格|搜索文本里需要保留空格，不想被识别成 AND||
|`&ver:`|`|`|搜索文件名带有竖线|
|`&excl:`|`!`|搜索文件名带有感叹号||
|`&lt:`|`<`|小于号||
|`&gt:`|`>`|大于号||
|`&quot:`|`"`|双引号||
|`&#<n>`|Unicode 十进制字符|||
|`&#x<n>`|Unicode 十六进制字符|||

示例：

1. 搜索文件名：`C:\Program Files`
    

```Plain
C:\Program&sp:Files
```

如果直接写 `Program Files`，空格会被解析成 AND！ 2. 搜索名称包含 `!readme.txt`

```Plain
&excl:readme.txt
```

如果你直接写 `!readme.txt`，会被理解成【排除 readme】，而不是搜索带感叹号的文件！ 3. 搜索名称包含 `"foo"`

```Plain
&quot:foo&quot:
```

## 六、最容易踩坑的关键点总结

1. **空格 = AND**，文件名里有空格，一定要用 `&sp:` 或者双引号；
    
2. `!` 放在搜索词前面是排除；如果！是文件名本身，要用`&excl:`转义；
    
3. OR 优先级高于 AND，复杂查询尽量用 `<>` 分组，避免逻辑出错；
    
4. 通配符 `*` 默认不跨文件夹，跨目录匹配用 `**`；
    
5. 区分「文件名 name」「路径 path」「主干 stem」「后缀 extension」，善用 `path:` / `extension:` 字段修饰；
    
6. 双引号仅关闭内部运算符，如果你引号内还要保留特殊符号，依然需要实体转义。
