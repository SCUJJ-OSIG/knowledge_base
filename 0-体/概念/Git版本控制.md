# Git版本控制

> 一句话定义：分布式版本控制系统，用于跟踪文件变化、协作开发和代码历史管理

## 核心原理

### 设计哲学

Git 的核心是**快照系统**而非差异系统。每次提交 (commit) 都是对项目完整状态的快照。

### 数据模型

```
工作区 (Working Directory)
    ↓ git add
暂存区 (Staging Area / Index)
    ↓ git commit
仓库 (Repository)
    ↓ git push
远程仓库 (Remote Repository)
```

### 三种状态

- **已提交 (committed)**：数据已保存在本地仓库
- **已修改 (modified)**：文件已修改但未暂存
- **已暂存 (staged)**：已标记要纳入下次提交

## 关键特性

### 分布式架构

- 每个开发者都有完整的代码历史
- 离线工作：大部分操作可在本地完成
- 多分支协作：分支成本低，鼓励频繁分支

### 内容寻址

- 所有数据通过 SHA-1 哈希值标识
- 文件、目录、提交都有唯一 ID
- 数据完整性保证

### 分支模型

- 分支是指向提交的指针
- HEAD 指向当前分支
- 合并、变基操作灵活
