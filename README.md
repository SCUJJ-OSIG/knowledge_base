# 知识库 · 技术文档

个人技术栈沉淀,扁平化结构 + frontmatter 分类 + 配合 `my-blog` 网站发布。

---

## 一、整体定位

这个仓库干三件事:

1. **博客底稿** — 写完后发布到 `my-blog` 网站
2. **自用工具/技能沉淀** — 自己的配置、最佳实践
3. **技术文章** — 系统性教程、踩坑记录

**核心目标**:降低归类与维护成本,内容只有一份,分类靠 frontmatter 不靠路径。

---

## 二、目录结构(v2.0 · 2026-07-31 扁平化)

> **重要**:v1.1 之后,**目录只服务于 vault 内部浏览,不承担任何分类/网站路由职责**。
> 分类、筛选、路由一律走 frontmatter 字段。

### 2.1 vault 根(扁平化区)

绝大多数笔记**直接放在 vault 根**,不再有 `0-体/`、`1-自用软件/` 这种分类目录。

## 三、frontmatter 分类(替代目录分类)

每个 .md 顶部必须有这些字段(即使空也要占位):

```yaml
---
tags: [网络, 教程] # 自由标签
形态: 教程型 # 参考型 | 教程型
场景: 部署 # 自由场景名(用于网站 chip 筛选)
published: true # 是否发到 my-blog 网站(只有 true 才发)
series: HTTP # 系列名(可选,用于 chip 筛选)
---
```

### 3.1 字段语义

| 字段        | 必填 | 用途                          | 网站体现         |
| ----------- | ---- | ----------------------------- | ---------------- |
| `形态`      | 否   | `参考型` / `教程型`           | 第一行 chip 筛选 |
| `场景`      | 否   | 自由字符串,如 `网络`/`部署`   | 第二行 chip 筛选 |
| `tags`      | 否   | 自由字符串数组                | 第三行 chip 筛选 |
| `published` | 否   | `true` 才发网站               | 数据库过滤       |
| `series`    | 否   | 系列名,用于系列文章 chip 筛选 | 第四行 chip 筛选 |

### 3.2 文件命名

- vault 根 .md 直接用标题名,不再强制 `[编号]-[标题]`
- 数字前缀(`0-`、`1-`、`2-`)剥掉,不参与分类
- 同名冲突时,加源目录前缀(如 `0-blog--未命名.md` → `blog-文字与形容词.md`)

## 四、配合 `my-blog` 网站发布

`my-blog`(Next.js 16)每天 0 点(UTC)通过 GitHub Action 拉取本仓库,生成静态网站。

### 4.1 发布流程

```
[本 vault] → git push → GitHub → Octokit 拉取 → gray-matter 解析 frontmatter
            → only published === true → 渲染成 posts/<slug>/
            → 部署到 GitHub Pages
```

### 4.2 发布开关

**唯一开关是 `published: true` 字段**。没写的 .md 不会出现在网站上。

### 4.3 视图配置

`views.published.base` 决定网站首页的 chip 栏结构。改这一个文件 = 改整个网站首页的筛选维度。

修改后直接 commit,push,等下次自动构建生效。

### 4.4 文章详情页(掘金式三栏)

`my-blog` 渲染的每篇 `posts/<slug>/` 页面是三栏布局:

```
┌─ 左 240px ─┬─ 中 flex-1(居中)─┬─ 右 240px ─┐
│  章节目录  │                  │  本文目录  │
│  (可收起)  │   文章正文       │  (可收起)  │
└────────────┴──────────────────┴────────────┘
```

左右栏由 `CollapsibleSidebar` 组件渲染,默认收起成 48px 宽竖条,localStorage 记忆状态。

**章节侧栏触发条件**:`frontmatter.series` 字段非空 且 同 vaultDir 下有多篇同系列文章。

## 五、图片资源规则

### 5.1 有图的 .md 独立子目录

**每个有图片的 .md 单独建一个同名子目录**,内含 `assets/`:

```
电脑相关权限问题/
├── 电脑相关权限问题.md
└── assets/
    └── image-20231111200427031.png
```

`.md` 里引用图片:

```markdown
![[image-20231111200427031.png]]            ← Obsidian 嵌入(推荐)
![alt](image-20231111200427031.png)         ← 标准 markdown 也能用
```

Obsidian 会按以下优先级找图:同目录 → 同名 .assets/ → 同名文件夹/assets/ → vault 根/assets/。

### 5.2 系统教程里的大图组

`2-技术文章/02-TypeScript全栈开发/前端框架/Vue生态/vue3ts尚硅谷/images/` 等**批量教学图**保留原结构,不动。

### 5.3 严禁

- 不要把图放在 vault 根 `assets/` 这种全局目录
- 不要让多篇 .md 共享一个 assets 目录(拆开)
- 不要用 `![](./相对路径/assets/...)` 跨多级目录(改不动)

## 六、wikilink 引用规则

### 6.1 嵌入 vs 跳转

| 语法          | 行为                                        | 用法               |
| ------------- | ------------------------------------------- | ------------------ |
| `![[文件名]]` | **嵌入**内容(图片直接显示,文本插入当前位置) | 图片、复用整段内容 |
| `[[文件名]]`  | **跳转**链接(点击跳到目标)                  | 文章间的引用       |

**默认用嵌入**(`![[]]`),除非明确只是"参见"。

### 6.2 路径稳定性

wikilink 优先用**文件名**,不要写路径。即使文件搬了家,Obsidian 也能找到:

```markdown
✅ [[HTTP协议详解与网络通信基础]] ← 稳定
❌ [[1-自用软件/01-编程基础/.../HTTP协议]] ← 脆弱,别写
```

## 七、去重原则

> **个人知识库的最大成本是「归类决策」,不是「内容重复」**。

1. **同一概念只写一份**。如果要写第二份,先想清楚是不是不同的"形态"(参考 vs 教程)。
2. **不同形态可以共存**:
   - `参考型`:速查、定义、命令片段
   - `教程型`:长文、推导、学习路径
3. 判定"是否重复":两份文件 > 70% 内容重叠才算重复,否则保留。
4. **绝不要为"将来会引用"提前抽离**。等第 3 次要抄同一段时才合并。

## 八、日常工作流

### 8.1 添加新笔记

1. 新建 .md,放在 vault 根(系统教程放对应子目录)
2. 写 frontmatter(至少 `形态` + `tags`)
3. 内容写完,如果想发网站 → 加 `published: true`
4. 图片放进同名子目录的 `assets/`

### 8.2 修改现有笔记

1. 直接编辑 .md
2. frontmatter 字段调整直接改 YAML
3. 改完 `git add` + `git commit`(按 CLAUDE.md 规则)

### 8.3 网站发布

1. 确保 .md 已有 `published: true`
2. push 到 main 分支
3. GitHub Action 每天 0 点(UTC = 北京时间 8 点)自动构建
4. 也可在 GitHub Actions 页面手动 `workflow_dispatch` 触发

### 8.4 跑迁移脚本

`scripts/` 下的脚本都支持 `--dry-run`,**先 dry-run 再实跑**:

```bash
bun scripts/xxx.ts --dry-run   # 看会改什么
bun scripts/xxx.ts             # 实跑
```
